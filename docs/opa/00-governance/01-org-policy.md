# 组织软件工程政策

| 属性 | 内容 |
|------|------|
| 文档编号 | OPA-POL-001 |
| 版本 | 1.0 |
| 适用 | 组织内全部软件项目 |
| 映射 | CMMI: OPF/OPD GP2.1；ISO 12207: 6.2.1 Life cycle model management |

## 1. 目的

规定本组织软件工程活动的基本原则，确保过程可裁剪、可执行、可改进，支撑向 CMMI 成熟度等级 3（已定义级）靠拢，并覆盖 ISO/IEC 12207 主要生命周期过程。

> 本文件为**过程资产**，不构成任何成熟度或认证声明。

## 2. 适用范围

- 组织自研、定制、维护类软件项目（默认假设：小型 Java/Web 团队）
- 含内部工具与对外交付产品
- 外包/合作开发须在合同中引用本政策关键条款

## 3. 基本原则

1. **过程优先于个人习惯**：项目须选用组织标准生命周期，并按《裁剪指南》记录裁剪。
2. **需求可追溯**：需求 → 设计 → 实现 → 测试 → 发布须可双向追溯。
3. **质量内建**：同行评审、测试与 PPQA 抽查并行，不以事后返工替代。
4. **变更受控**：基线化工作产品变更须走变更请求（CR）。
5. **风险与决策显性化**：关键风险登记；重大技术/商务决策使用 DAR。
6. **度量驱动改进**：采集少量可落地指标，支撑 OPF 改进。
7. **能力与培训**：关键角色须满足 OT 培训要求后方可独立上岗。

## 4. 角色与职责（组织级）

| 角色 | 职责 |
|------|------|
| 组织过程负责人（OPF Owner） | 维护 OPA、审批重大裁剪、推动改进 |
| 项目经理（PM） | 立项/计划/监控、裁剪申请、度量上报 |
| 技术负责人（TL） | 设计与实现质量、技术风险 |
| QA/PPQA | 过程符合性检查、评审记录归档抽查 |
| CM 管理员 | 配置项、基线、发布包 |
| 全员 | 按已定义过程与模板执行 |

小型组织允许一人兼任多角，但 **PPQA 与被检查活动执行人宜分离**（至少交叉检查）。

## 5. 强制要求（不可随意裁剪）

- 书面项目计划（可简版）与范围/里程碑
- 需求基线与变更控制
- 至少一类验证（单元/集成/系统）与发布前确认记录
- 配置管理与可复现构建/发布
- 项目结项或阶段回顾（含改进建议）
