# 过程裁剪指南

| 属性 | 内容 |
|------|------|
| 文档编号 | OPA-TAIL-001 |
| 版本 | 1.0 |
| 映射 | CMMI: OPD SP1.3, IPM；ISO 12207: 6.2.1（生命周期模型裁剪） |

## 1. 目的

允许项目在组织标准过程上做**有记录的裁剪**，既保持一致性，又适配项目规模与风险。

## 2. 裁剪原则

1. **先选模型，再裁剪活动**：默认迭代增量；极小修复可选“快速通道”。
2. **风险越高，过程越完整**：对外交付、安全/资金相关、多人协作 → 少裁剪。
3. **不可裁剪项**见组织政策第 5 节（计划、需求基线、验证、CM、回顾）。
4. **裁剪须书面批准**：PM 填写裁剪表，OPF Owner（或授权人）审批后纳入项目计划附录。

## 3. 项目分类（裁剪起点）

| 类型 | 特征 | 建议完整度 |
|------|------|------------|
| A 标准交付 | 新功能/对外/工期≥4 周 | 标准过程全套，轻量模板 |
| B 小迭代 | 已有产品增量、1–2 人、≤2 周 | 可合并文档、简化 DAR/正式培训 |
| C 紧急修复 | 生产缺陷/热修 | 快速通道：最小变更+验证+发布记录 |
| D 探索/Spike | 技术预研 | 目标与结论记录即可；产出若入库需补 CM |

## 6. 禁止的裁剪

- 无需求/无范围说明即开工（探索类除外且不得直接发布生产）
- 无任何验证记录即发布生产
- 绕过配置库私自发布
- 删除度量中的**强制最小集**（见度量定义）且无替代指标
