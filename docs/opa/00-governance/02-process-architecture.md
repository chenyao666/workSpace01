## 1. 架构总览

本组织过程资产（OPA）分为四层：

```
┌─────────────────────────────────────────────────────────┐
│  L0 治理层：政策、架构、裁剪、改进、培训（OPF/OPD/OT）   │
├─────────────────────────────────────────────────────────┤
│  L1 项目管理层：立项/计划/监控/风险/CM/度量/PPQA/DAR    │
├─────────────────────────────────────────────────────────┤
│  L2 工程生命周期层：需求→设计→实现→V&V→发布→维护         │
│      （对齐 ISO 12207 技术过程 + 部分支持过程）          │
├─────────────────────────────────────────────────────────┤
│  L3 工作产品层：模板、检查单、度量定义、培训记录         │
└─────────────────────────────────────────────────────────┘
```

## 3. 标准生命周期模型（默认）

小型 Java/Web 项目默认采用**迭代增量 + 阶段门禁**：

```
立项 → 计划 → [迭代: 需求细化→设计→实现→验证]ₙ → 确认/发布 → 维护
         └──────── PMC / RSKM / CM / MA / PPQA 贯穿 ────────┘
```

阶段门禁（可裁剪为轻量检查表）：

| 门禁 | 进入条件 | 主要输出 |
|------|----------|----------|
| G0 立项 | 业务目标清晰 | 立项记录、初步范围 |
| G1 计划基线 | 计划评审通过 | 项目计划、风险初版 |
| G2 需求基线 | 需求评审通过 | SRS、追溯矩阵初版 |
| G3 就绪发布 | 测试通过+变更关闭 | 发布包、确认记录 |
| G4 结项/移交 | 维护交接完成 | 结项报告、改进项 |

## 4. 过程接口（简图说明）

- **REQM/RD → TS/PI**：需求条目驱动设计与实现任务拆分
- **VER/VAL ↔ 发布**：验证失败阻断发布；确认由干系人签字/书面同意
- **CM**：对需求、设计、代码、构建脚本、发布包建立配置项
- **PPQA**：按计划抽查过程与工作产品，结果进改进库
- **MA**：度量入库，供 PMC 监控与 OPF 改进分析
- **OT**：角色能力缺口由培训计划关闭

## 5. 资产维护

- OPA 变更走组织级变更（可由 OPF Owner 审批）
- 重大过程变更需试点项目验证后再全面推广（OPF）
- 版本号：主版本.次版本；本包起始 1.0
