# 设计过程规程

| 属性 | 内容 |
|------|------|
| 文档编号 | OPA-LC-DES-001 |
| 版本 | 1.0 |
| 映射 | CMMI: TS；ISO 12207: 6.4.3 System architectural design, 6.4.4 Design |

## 1. 目的

将已基线需求转化为可实现的体系结构与详细设计，识别技术风险与接口。

## 2. 入口 / 出口

**入口**：相关需求已评审（或本迭代范围已冻结）。  
**出口**：设计说明（或等价物）已评审；关键接口与数据模型明确；实现任务可分解。

## 3. 主要活动

1. **架构选型**：必要时走 DAR（技术栈、中间件、集成方式）。
2. **体系结构设计**：模块/服务边界、部署视图、主要数据流。
3. **详细设计**：关键类/API、库表、状态机、异常与安全控制点。
4. **编写设计说明**：使用 [设计说明模板](../04-templates/design-spec.md)。
5. **设计评审**：使用 [设计检查单](../03-quality/03-checklist-design.md)。
6. **更新追溯**：需求 ID → 设计元素。

## 4. 工作产品

- 设计说明 / 架构图（可用 PlantUML/附图）
- 接口清单、数据字典（可嵌入设计说明）
- 评审记录；重大决策记录（DAR）

## 5. 质量要点

- 每个高优先级需求至少映射到一个设计元素
- 外部接口有契约（字段、错误码、鉴权）
- 非功能需求有对应设计策略（缓存、限流、审计等）

## 6. 裁剪提示

- B 类：PR/Wiki 中的设计笔记 + 一张架构草图即可。
- 纯 UI 文案类变更可省略独立设计说明。
