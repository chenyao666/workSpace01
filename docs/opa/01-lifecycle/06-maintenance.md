# 维护过程规程

| 属性 | 内容 |
|------|------|
| 文档编号 | OPA-LC-MNT-001 |
| 版本 | 1.0 |
| 映射 | CMMI: 相关工程 PA + REQM/CM；ISO 12207: 6.4.10 Software maintenance, 6.4.11 Disposal（如适用） |

## 1. 目的

对已交付软件进行纠错、适应、完善与预防性维护，保持可服务性与资产受控。

## 2. 维护类型

| 类型 | 说明 | 典型入口 |
|------|------|----------|
| 纠错 | 修复缺陷 | 问题报告 |
| 适应 | 环境/法规/依赖变更 | 变更请求 |
| 完善 | 增强功能/体验 | 需求/变更 |
| 预防 | 重构、升级、安全加固 | 技术债清单 / DAR |

## 3. 主要活动

1. **接收与分诊**：记录问题/变更；严重级别与 SLA（组织可自定）。
2. **影响分析**：波及模块、数据、接口、用户；估时与风险。
3. **实施**：复用生命周期过程（需求→…→发布），按类型裁剪。
4. **回归验证**：至少覆盖缺陷相关路径与约定冒烟集。
5. **关闭与知识沉淀**：根因分类；更新 FAQ/运维笔记；度量计入缺陷密度等。
6. **退役（如需要）**：数据迁移/归档、访问关闭、资产标记废弃。

## 4. 工作产品

- 问题报告 / 变更请求及处置记录
- 维护版本发布说明
- 已知问题与技术债列表

## 5. SLA 建议（可裁剪）

| 严重级别 | 含义 | 响应 | 目标修复 |
|----------|------|------|----------|
| S1 | 生产不可用/数据风险 | 1h | 协商热修 |
| S2 | 主要功能受损 | 4h | 下一工作日内方案 |
| S3 | 次要功能 | 1 工作日 | 计划版本 |
| S4 | 体验/建议 | 评估后排期 | 待定 |

## 6. 裁剪提示

- 维护项目可建立「维护背书计划」代替完整立项，但仍需版本与 CM。
