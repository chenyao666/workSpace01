# 发布与移交过程规程

| 属性 | 内容 |
|------|------|
| 文档编号 | OPA-LC-REL-001 |
| 版本 | 1.0 |
| 映射 | CMMI: PI, VAL, CM；ISO 12207: 6.4.8 Transition, 6.4.9 Validation |

## 1. 目的

将通过验证/确认的软件以可控方式交付运行环境，并完成知识与资产移交。

## 2. 入口 / 出口

**入口**：发布候选构建通过门禁；变更与阻断缺陷关闭或豁免批准；发布说明就绪。  
**出口**：生产（或约定环境）部署成功；移交清单签收；回滚方案可用。

## 3. 主要活动

1. **发布准备**：冻结发布内容清单（需求/缺陷 ID）；打版本标签（CM）。
2. **发布说明**：新功能、修复、已知问题、依赖与配置变更、回滚步骤。
3. **部署演练**（建议）：在预发验证安装与冒烟。
4. **批准发布**：PM + TL（及客户代表如需要）确认。
5. **执行部署**：按脚本/清单；双人复核关键操作（生产）。
6. **发布后验证**：冒烟/监控；问题按严重级别响应。
7. **移交**：运维手册要点、账号/配置交接、培训（如需要）。

## 4. 发布检查最小集

- [ ] 版本号与标签一致
- [ ] 构建可复现，产物校验（校验和/镜像 digest）
- [ ] 配置与密钥来源明确（非硬编码）
- [ ] 数据库变更可回滚或有前进修复方案
- [ ] 回滚步骤已演练或书面可行
- [ ] 支持/值班联系人明确

## 5. 工作产品

- 发布说明、部署记录、标签/基线记录
- 移交清单、发布后问题单（如有）

## 6. 裁剪提示

- 内部工具：可简化批准链，但仍须标签与回滚说明。
- 热修：走 C 类裁剪，事后 24–48h 内补全发布记录。
