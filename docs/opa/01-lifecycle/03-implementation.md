# 实现与集成过程规程

| 属性 | 内容 |
|------|------|
| 文档编号 | OPA-LC-IMP-001 |
| 版本 | 1.0 |
| 映射 | CMMI: TS, PI；ISO 12207: 6.4.5 Implementation, 6.4.7 Integration |

## 1. 目的

按设计实现可构建、可集成的软件单元，并完成组件/系统集成。

## 2. 入口 / 出口

**入口**：本迭代范围与设计要点明确；开发环境就绪。  
**出口**：代码合入主线（或发布分支）；构建通过；单元/集成验证达到门禁；工作产品受 CM 控制。

## 3. 主要活动

1. **任务分解**：关联需求/缺陷 ID；估算与认领。
2. **编码实现**：遵循团队编码规范；密钥与配置不入库明文。
3. **单元验证**：关键逻辑有自动化测试或等价检查。
4. **代码同行评审**：使用 [代码检查单](../03-quality/04-checklist-code.md)；合并前至少一人审查。
5. **持续集成**：本地/CI 构建；修复失败构建优先于新功能。
6. **集成**：按依赖顺序集成模块；记录集成问题到问题报告。
7. **更新追溯**：需求/设计 → 提交/模块。

## 4. 工作产品

- 源代码与构建脚本
- 代码评审记录（PR/评审表）
- 单元/集成测试资产
- 已知问题列表

## 5. 门禁（建议）

- CI 绿灯；无未评审的关键路径合入
- 阻断级缺陷清零；高级别缺陷有明确豁免与计划

## 6. 裁剪提示

- 单人微型项目：可用自检清单代替正式评审，但发布前仍建议他人抽看。
- Spike 代码若进入产品，须补评审与测试。
