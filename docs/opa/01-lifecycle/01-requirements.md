# 需求过程规程

| 属性 | 内容 |
|------|------|
| 文档编号 | OPA-LC-REQ-001 |
| 版本 | 1.0 |
| 映射 | CMMI: REQM, RD；ISO 12207: 6.4.1 Stakeholder needs, 6.4.2 System/Software requirements |

## 1. 目的与范围

获取、分析、规格化、基线化并管理软件需求；保持需求变更受控与可追溯。

## 2. 入口 / 出口准则

**入口**：立项批准或迭代目标确认；干系人可接触。  
**出口**：需求基线建立；开放问题已登记；追溯矩阵初版可用。

## 3. 主要活动

1. **识别干系人与需要**（RD）：访谈/原型/既有系统分析，记录业务目标与约束。
2. **导出软件需求**：功能、非功能（性能、安全、可用性）、接口、数据。
3. **编写 SRS**：使用 [需求规格模板](../04-templates/requirements-spec.md)。
4. **需求评审**：使用 [需求检查单](../03-quality/02-checklist-requirements.md)。
5. **基线化**：CM 纳入需求基线；分配需求 ID（如 REQ-xxx）。
6. **变更管理**：基线后变更走 [变更请求](../04-templates/change-request.md)；影响分析后更新追溯。
7. **双向追溯**：需求 ↔ 设计/代码/用例；PMC 阶段检查覆盖空洞。

## 4. 角色

| 角色 | 活动 |
|------|------|
| 分析/产品 | 收集与编写需求 |
| PM | 优先级、范围承诺 |
| TL/开发 | 可行性、工作量反馈 |
| QA/测试 | 可测性审查 |
| 干系人 | 确认与验收标准 |

## 5. 工作产品

- 干系人需要列表（可附在 SRS 附录）
- 软件需求规格（SRS）
- 需求追溯矩阵（RTM，可表格）
- 评审记录、变更请求

## 6. 裁剪提示

- B 类：SRS 可缩为「用户故事 + 验收标准」表。
- C 类：缺陷单中的「期望行为」即需求，须回归验证。
