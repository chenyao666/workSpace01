# 度量与基线定义

## 1. 目的

定义组织**强制最小度量集**与可选指标，给出操作定义与初始基线用法。数值基线应在积累 2–3 个项目后校准；下表提供起步目标供参考，**非认证承诺**。

## 2. 强制最小集（不可裁剪为“不采集”）

| ID | 指标 | 操作定义 | 采集频率 | 用途 | 起步参考目标 |
|----|------|----------|----------|------|--------------|
| M1 | 里程碑达成率 | 按期完成里程碑数 / 计划里程碑数 | 里程碑 | PMC | ≥ 80% |
| M2 | 范围变更率 | 基线后已批准 CR 数 / 基线需求数 | 结项或版本 | REQM/PMC | 监控趋势 |
| M3 | 发布前致命缺陷 | 发布候选中开放的 S1 数 | 发布前 | VER | = 0 |
| M4 | 逃逸缺陷数 | 发布后 30 天内新发现缺陷（S1–S3） | 版本+30天 | VAL/OPF | 逐版下降 |
| M5 | 代码评审覆盖率 | 合入 main 的变更中经评审的比例 | 迭代 | VER | ≥ 90% |

## 3. 推荐可选集

| ID | 指标 | 操作定义 | 说明 |
|----|------|----------|------|
| O1 | 需求稳定性 | 基线后需求变更条数 | 与 M2 互补 |
| O2 | 测试通过率 | 通过用例 / 执行用例 | 注意勿牺牲覆盖换通过率 |
| O3 | 平均修复时长（MTTR） | 缺陷从确认到验证关闭 | 按严重级别分组 |
| O4 | 构建成功率 | CI 成功次数 / 总构建 | 工程健康 |
| O5 | 同行评审缺陷密度 | 评审发现问题 / 页或 KLOC | 早期质量 |

## 4. 基线管理

1. **组织基线**：每年或每 N 个项目由 OPF Owner 更新参考目标。
2. **项目目标**：可严于组织基线，写入项目计划。
3. **解读优先于达标**：异常先分析原因（范围狂飙、测试不足等），禁止单纯“刷指标”。

## 5. 数据存储

- 推荐：共享表格或项目 Wiki「度量」页 + 结项汇总拷贝至组织度量库目录。
- 保留期：至少 4 个季度，供改进对比。
